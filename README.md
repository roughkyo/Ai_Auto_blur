# AI_Auto_Blur 실습 Lab

**Yangphago_세상을 이롭게 하는 AI 프로젝트**

사진 속 사람과 얼굴을 탐지하고, 신뢰도 임계값·NMS·블러·모자이크를 직접 조작하며 배우는 웹 학습 사이트입니다.

저장소: [roughkyo/Ai_Auto_blur](https://github.com/roughkyo/Ai_Auto_blur)

## 기능

- JPG·PNG·WebP 업로드 및 카메라 정지 사진 촬영
- YOLOv8n 사람 후보 탐지와 BlazeFace 얼굴 탐지
- 신뢰도 임계값·NMS IoU 기준 조절, 후보별 점수와 처리 사유 확인
- 얼굴 블러·모자이크, 강도·여유 폭 조절, 누락 얼굴 수동 보정
- 가림 결과 PNG 다운로드
- 단계별 할 일·관찰·질문과 후보 예측 과정 관찰
- 5지선다형 3문항, 초해상도와 블러·모자이크의 관계를 묻는 주관식 1문항

과정 관찰의 특징 추출 그림은 개념도이며, 후보를 차례로 표시하는 순서는 모델 내부의 실제 연산 순서가 아닙니다. 사람 임계값을 변경할 때 모델을 다시 학습하거나 추론하지 않고 저장된 후보에 기준을 다시 적용합니다.

## 로컬 실행

Python 3이 있는 환경에서 저장소 루트에서 실행합니다. npm 설치·빌드·외부 AI API 키는 필요하지 않습니다.

```sh
# 사이트 폴더의 정적 파일만 현재 PC에 제공합니다.
python -m http.server 5173 --bind 127.0.0.1 --directory 2026-09-13-auto-blur-site
```

[로컬 사이트](http://127.0.0.1:5173/)에 접속합니다. HTML 파일을 직접 더블클릭하는 `file://` 방식은 사용하지 않습니다. 카메라는 HTTPS 또는 localhost 환경과 사용자의 권한 허용이 필요합니다.

## GitHub–Vercel 배포

1. 이 저장소를 Vercel에서 Import합니다.
2. **Root Directory:** `2026-09-13-auto-blur-site`
3. **Framework Preset:** `Other`
4. **Build Command / Install Command:** 비움
5. **Output Directory:** `.`
6. 배포 후 HTTPS 환경에서 모델 로딩, 사진 업로드, 카메라 권한·촬영·종료, PNG 저장을 확인합니다.

전체 작업 폴더를 정적 서버의 공개 루트로 지정하지 마세요. 사이트 폴더 안의 파일은 웹에서 접근 가능한 공개 자료로 취급해야 합니다. 현재 공개 배포 URL은 아직 확정되지 않았습니다.

## 사진·카메라·답안 처리

- 사진과 주관식 답안은 브라우저 메모리에서 처리합니다. 애플리케이션에는 이를 업로드하는 API나 영구 저장 기능이 없습니다.
- 사진·영상·마이크 입력을 외부 AI 서비스로 전송하지 않습니다. 음성 권한도 요청하지 않습니다.
- 카메라는 버튼을 눌러 허용한 경우에만 사용하며, 촬영·닫기·입력 교체·페이지 이탈 시 트랙을 종료합니다.
- 파일은 15MB 이하, 디코드 후 2천만 픽셀 이하를 허용하고 긴 변을 최대 1600px로 줄입니다. 저장 이미지도 작업 해상도를 사용합니다.
- 모델·라이브러리 파일 다운로드와 호스팅 접속 기록은 사진 업로드와 별개입니다. 호스팅 사업자는 일반적인 접속 로그를 처리할 수 있습니다.
- 탐지 누락이나 잘못된 가림이 발생할 수 있습니다. 원본 비교와 수동 보정을 거쳐야 하며, 얼굴 가림만으로 완전한 익명화를 보장하지 않습니다.

## 보안 점검과 배포 전 남은 사항

2026-09-13 로컬 점검에서 일반적인 비밀키 패턴은 발견하지 못했으며, 포함된 JS/WASM 8개가 해당 버전의 npm 원본과 일치했습니다. 두 npm 패키지 버전의 OSV 질의에서는 등록된 취약점 결과가 없었습니다. 이 결과는 모든 취약점의 부재, 네이티브 내부 구성요소의 안전성 또는 배포 환경의 보안을 보장하지 않습니다.

현재 남은 사항:

- 공개 문서의 개발 PC 절대 경로는 저장소 기준 설명으로 정리했습니다.
- 프로젝트에 CSP, 프레임 삽입 제한 등 명시적인 배포 보안 헤더 설정이 없습니다. 실제 런타임의 WASM 요구사항을 포함해 배포 설정과 함께 검증해야 합니다.
- 큰 이미지의 해상도 제한은 디코드 이후에 확인됩니다. 디코드 순간의 메모리 사용과 기기별 멈춤 가능성이 남아 있습니다.
- 이 점검에서는 GitHub 계정 설정·보호 규칙과 실제 Vercel HTTPS 응답을 검증하지 않았습니다.

상세 로컬 점검 보고서는 작업 폴더에 별도로 보관하며, 개발 PC 경로와 점검 자료가 포함될 수 있어 기본 커밋 대상에서 제외했습니다.
